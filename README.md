# ABS Project - DSCI 470/STAT 495
Authors: August Decz, Coleton Grossman, Greg Matthews, Steven Pappas, and Oliver Schramm

This repository stores all of the code files for our ABS (Automated Balls and Strikes) project.

GOALS:
- **Optimal Stopping Theory:** We want to determine WHEN it is most valuable for a hitter or a catcher to use one of their ABS challenges.
- **Modeling:** We want to model the probability that hitters and catchers challenge *when they should* and *when they shouldn't*. This is 
  the first phase of this project.
  - **Response:** `challenge_hitter` / `challenge_catcher` (was the pitch challenged?)
  - **Covariates:** Pitch location (x and z), change in run expectancy ($\delta$), game state (outs, balls, strikes, inning),
                    challenges remaining
  - **Random Effects ($\gamma$):** Batter, Umpire, Pitcher, Catcher
  - **Sample:** ~647k pitches, 2026-03-25 through 2026-09-09 (as of 2026-09-21)

## 3. Run order

```
get_statcast.R      # ONE TIME (or when refreshing data)
                    #   -> data/statcastlist_26.parquet
                    #   -> data/home_plate_umps.csv
      |
      v
data.R              # builds every analysis frame in memory
      |
      +--> model_work.R        # the models (main file)       [sources data.R itself]
      +--> eda_work.R          # exploratory tables, ANOVAs   [sources data.R itself]
      +--> model_testing.R     # k-fold CV for spline df      [needs data.R first]
      +--> visualizations.R    # plots and gt tables          [needs data.R first]
```

`data.R` is the only script that reads raw files, and everything downstream assumes its
objects are in the global environment. `model_work.R` and `eda_work.R` call
`source("data.R")` at the top, so you can open either cold. `model_testing.R` and
`visualizations.R` do not — run `data.R` (and, for `model_testing.R`, `model_work.R`)
first.

The dependency runs one way: `get_statcast.R` writes files, `data.R` reads them. Keep it
that way — `get_statcast.R` must never `source("data.R")`, because on a fresh clone
`data.R` would be reaching for umpire data that `get_statcast.R` hasn't written yet.

### What `data.R` leaves in your environment

| Object | Rows | What it is |
|---|---|---|
| `statcastlist_26` | 647,529 | Raw season Statcast, all pitch outcomes |
| `challenge` | 6,976 | The three Savant challenge exports stacked, with `call_change` flags |
| `playerid` | 520,934 | `key_mlbam` → `"Last, First"` |
| `umps` | 2,195 | `game_pk` → home-plate umpire |
| `modeldata` | 286,687 | Challenges + all takeable pitches, deduped, adjusted location/movement |
| `runexpectancies` | 576 | Mean Δrun-expectancy by base-out-count-outcome state |
| `runexpectancies2` | 576 | Self-join of the above: the ball-vs-strike pair for each state |
| `modeldata2` | 286,687 | `modeldata` + `delta` |
| `chase` | 490 | Per-batter chase profile, keyed on `batter` |
| `modeldata_hitter` | 102,373 | Hitter-model frame: + `challenges_remaining`, `umpire_hp` |
| `modeldata_catcher` | 181,140 | Catcher-model frame: same |

Key derived variables:

- **`plate_x_adj` / `plate_z_adj`** — location re-centered so positive x is always inside
  to the batter and z is relative to the middle of that batter's strike zone. Use these,
  not raw `plate_x` / `plate_z`, in models.
- **`delta`** — absolute run-expectancy difference between the call as made and the call
  reversed, for that base-out-count state. The "how much does this pitch matter"
  predictor. Note it is a **state-level** value: every pitch sharing a state gets an
  identical `delta`.
- **`challenges_remaining`** — 2 per team, +1 in extras, counting down only on *lost*
  challenges. Built separately for each side because hitters and catchers burn their own.
- **`inning`** — capped at `extra_inning_cap` (`data.R:11`, currently 10), so all extra
  innings bin together. The cap is applied twice on purpose: once on `challenge` so the
  EDA tables in `eda_work.R` bin correctly, and once on `modeldata` after the rbind so
  the Statcast rows get it too. Clamping is idempotent, so applying it twice is safe.
  **If you change the constant, both copies must stay in agreement** — if they drift,
  challenged and un-challenged pitches land in different bins and extra innings become
  perfectly predictive of "not challenged."

### Model naming

`mod{N}_call_change_{hitter,catcher}`, where `N` is model complexity:
`mod0` = location only, `mod1` = location + game state (fixed effects, `glm`),
`mod2` = `mod1` + random effects for batter, catcher, both teams, and umpire (`glmer`).
Suffix `_red` = the reduced model in a likelihood-ratio comparison.

## 6. Things to keep in mind

None of the following will block your work, but they are rabbit holes. Brayan Bello almost 
poisoned the well.

- **`N` in `runexpectancies` is off by one in two states.** It's `n()`, which counts rows,
  while the means next to it are now computed with `na.rm = TRUE` over a smaller set. Two
  pitches in the 2026-03-31 Bello at-bat (game `824212`, at-bat 43) have a null
  `delta_run_exp` straight from Statcast. Harmless unless you use `N` as a weight or to
  filter thin states — use `sum(!is.na(delta_run_exp))` if you need it exact.
- **Never drop the `na.rm = TRUE` from `data.R:105`.** Those same two pitches poison their
  whole state's mean without it, and because `delta` differences each state against its
  ball/strike partner, the NA spreads to the partner too — 2 bad pitches silently cost
  483 rows, which `glm` then drops via `na.omit` without saying anything. Worth a
  `stopifnot(!any(is.na(modeldata2$delta)))` at the end of `data.R` to catch the next
  Statcast gap loudly.
- **`delta_runexp` and `scorediff`** (`data.R:101-102`) are computed inside the
  `runexpectancies` mutate and then dropped — they never reach the `reframe` output. Dead
  code today. If you promote either to a predictor, the NA problem above resurfaces at the
  pitch level and you'll need to reconstruct those two values rather than just skip them.
- **The cap condition is a literal `9`** — `inning > 9 ~ extra_inning_cap`. Both copies
  agree, so nothing is wrong now, but setting the constant to 11 would push real 10th
  innings up to 11. `pmin(inning, extra_inning_cap)` closes that if you ever change it.
- **`model_work.R` still loads `httr`, `httr2`, and `jsonlite`.** Left over from when the
  umpire scrape lived there; it moved to `get_statcast.R`. Harmless, just misleading about
  what the file does.
